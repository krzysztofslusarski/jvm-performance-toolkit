Safepoint & GC Log Analyzer

Upload your JVM GC and safepoint logs for analysis

This page is under heavy development. If you have any issues, contact ks@gclogs.com.

Before you upload

  • Logs from JDK 11, 17, 25 and 27 — work with the flags below, tested with Parallel, G1, ZGC (JDK 17+) and Shenandoah (also generational on JDK 25+) on Linux and macOS, with both dot and comma decimal separators (e.g. the pl_PL locale).
  • Logs from JDK 9, 10 and the versions between the tested ones — should work.
  • Logs from JDK 8 — GC logs of G1 and Parallel and safepoint statistics, with the flags below. Choose JDK 8 in the upload form.
  • CMS is not supported (JDK 8 CMS logs do not work, JDK 9–13 CMS logs have not been tested).
  • Choose the JDK and the collector that produced the logs in the upload form (the gcCollector field with cURL).
  • Max MB file (after compression).
  • For JDK 9+ decorators: level, tags, time, uptime are needed. Check sample Xlog configuration below.
  • You can add many log files in one zip/7z archive. Files will be ordered by the uptime of their first line (JDK 8 files keep the archive order).

Upload with cURL

Compress your logs:

zip -r logs.zip logs_file.log*

Make sure your logs are not bigger than MB after compression.

Upload logs archive to the server:

curl -X POST --form file=@./logs.zip [[${enqueueUrl}]]

Logs other than G1 / Parallel from JDK 9+ need the parser: add --form gcCollector=SHENANDOAH, --form gcCollector=ZGC or --form gcCollector=JDK8.

In response you'll receive a link to your report. The report will be available for [[${parsingProperties.results.expiration.toMinutes()}]] minutes.

Kubernetes
kubectl exec -t <pod> -- curl -X POST --form file=@<path> [[${enqueueUrl}]]

The curl command must be available in the container.

Recommended JVM Arguments
VM Args for all statistics (JDK 11+) 
-Xlog:codecache=info,
codecache+sweep*=trace,
class+unload,
class+load,
os+thread,
safepoint,
gc*,
gc+stringdedup=debug,
stringdedup*=debug,
gc+ergo=trace,
gc+age=trace,
gc+phases=trace,
gc+humongous=trace,
gc+heap=trace,
gc+tlab=trace,
jit+compilation=debug
:file=/tmp/app.log
:level,tags,time,uptime
:filesize=104857600,filecount=5
Simplest VM Args to add JDK > 8 
-Xlog:safepoint,
gc*,
gc+heap=trace,
gc+age=trace,
gc+phases=trace,
gc+humongous=trace
:file=/tmp/app.log
:level,tags,time,uptime
VM Args for JDK 8 
-XX:+PrintGCDetails
-XX:+PrintGCDateStamps
-XX:+PrintGCTimeStamps
-XX:+PrintTenuringDistribution
-XX:+PrintGCApplicationStoppedTime
-XX:+PrintGCApplicationConcurrentTime
-XX:+PrintSafepointStatistics
-XX:PrintSafepointStatisticsCount=1

JDK 8 prints the GC log and the safepoint statistics to the standard output, save it to a file, e.g. java ... > /tmp/app.log. Do not add -Xloggc (the GC log would be separated from the safepoint statistics) nor -XX:+LogVMOutput (it escapes the output as XML).

Unified logger — changing logs at runtime 
sudo -u JVM_USER jcmd `pgrep -x java` VM.log
output="file=/PATH/TO/gc.log"
output_options="filesize=104857600,filecount=5"
what="codecache=info,codecache+sweep*=trace,class+unload,class+load,os+thread,safepoint,gc*,gc+stringdedup=debug,stringdedup*=debug,gc+ergo=trace,gc+age=trace,gc+phases=trace,gc+humongous=trace,gc+heap=trace,gc+tlab=trace,jit+compilation=debug"
decorators="level,tags,time,uptime,pid"
